# Архитектура проекта Radar

## Обзор

Radar - это Telegram Mini App для создания цифровых визиток, обмена контактами и делового нетворкинга.

## Структура проекта

```
radar_bot/
├── backend/                 # NestJS backend
│   ├── src/
│   │   ├── main.ts         # Точка входа
│   │   ├── app.module.ts   # Главный модуль
│   │   ├── auth/           # Модуль аутентификации
│   │   ├── user/           # Модуль пользователей
```

## Архитектурные решения (ADR)

### ADR-001: React + TypeScript
**Решение:** Использовать React с TypeScript для фронтенда.

**Преимущества:**
- Компонентный подход
- Статическая типизация
- Большая экосистема библиотек
- Поддержка Telegram WebApp SDK

### ADR-002: NestJS
**Решение:** Использовать NestJS для бэкенда.

**Преимущества:**
- Модульная архитектура
- Встроенная поддержка TypeScript
- Декораторы и DI
- Легкая интеграция с Telegram

### ADR-003: PostgreSQL
**Решение:** Использовать PostgreSQL как основную БД.

**Преимущества:**
- ACID транзакции
- JSON поля для гибких данных
- Надежность и производительность

### ADR-004: Prisma ORM
**Решение:** Использовать Prisma для работы с БД.

**Преимущества:**
- Типобезопасность
- Автогенерация типов
- Удобная миграция данных

### ADR-005: Zustand
**Решение:** Использовать Zustand для state management.

**Преимущества:**
- Минималистичный API
- Малый размер
- Отсутствие бойлерплейта

### ADR-006: Swiper.js
**Решение:** Использовать Swiper.js для карусели визиток.

**Преимущества:**
- Сенсорное управление
- Адаптивность
- Плавные анимации

## Поток данных

### 1. Аутентификация

```
Telegram WebApp → Frontend → Backend (/api/auth/validate)
                              ↓
                        Проверка initData
                              ↓
                        Создание/обновление пользователя
                              ↓
                        Генерация JWT токена
                              ↓
Frontend ← Токен ←────────────┘
  ↓
Сохранение токена в localStorage
```

### 2. Создание визитки

```
Frontend (форма) → Backend (POST /api/business-cards)
                              ↓
                        Валидация данных
                              ↓
                        Генерация contactId (UUID)
                              ↓
                        Создание QR-кода
                              ↓
                        Сохранение в БД
                              ↓
Frontend ← Визитка ←──────────┘
  ↓
Обновление UI
```

### 3. Реферальная система

```
Пользователь А → Копирует реферальную ссылку
                      ↓
Пользователь Б → Переходит по ссылке
                      ↓
Открытие визитки Пользователя А
                      ↓
Нажатие "Сохранить контакт"
                      ↓
Backend (POST /api/contacts/add-by-ref)
                      ↓
Проверка contactId (дубликат?)
                      ↓
Добавление контакта в БД
                      ↓
Логирование реферала (referral_logs)
                      ↓
Начисление баллов рефереру
                      ↓
Обновление баланса
```

### 4. Регистрация на событие

```
Frontend → Backend (POST /api/events/:id/register)
                    ↓
Проверка активности события
                    ↓
Проверка дубликата регистрации
                    ↓
Создание записи в event_registrations
                    ↓
Отправка уведомления (Telegram)
                    ↓
Frontend ← Подтверждение ←─┘
```

## Безопасность

### Аутентификация
- Валидация Telegram initData на сервере
- JWT токены для защиты API
- HttpOnly cookies (опционально)

### Защита данных
- Валидация всех входных данных (class-validator)
- Защита от XSS и CSRF
- Rate limiting для API endpoints

### Приватность
- Доступ к визиткам только по contactId (UUID)
- Контакты приватны для каждого пользователя
- Реферальные связи не публичны

## Масштабируемость

### Горизонтальное масштабирование
- Stateless backend
- Redis для сессий и кеширования
- Балансировка нагрузки через Nginx

### Вертикальное масштабирование
- Индексы в PostgreSQL
- Оптимизация запросов Prisma
- Кеширование частых запросов

## Мониторинг

### Логи
- Winston для логирования
- Структурированные логи (JSON)
- Разделение по уровням (error, warn, info)

### Метрики
- Количество пользователей
- Активные визитки
- Реферальная активность
- Регистрации на события
